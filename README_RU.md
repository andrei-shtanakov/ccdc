# CCDC 2026.2.0: установка и пользовательская конфигурация

Рецепт `ccdc-2026.2.0-GCCcore-12.3.0.eb` устанавливает полный комплект CCDC.
После установки каталог `ccdc-data/csd` переименовывается в
`ccdc-data/csd.installer`. На прежнем месте **не создаются ни ссылка, ни каталог**.
Содержимое `csd.installer`, включая `.inf`, SQLite-файлы и `subsets`, затем
копируется вручную в `/db/ccdc/csd/csd/2026/ccdc-data/csd/`.

## Архив скриптов

Скрипты настройки хранятся отдельно от easyconfig. Для сборки нужны два источника:

- `CSDInstallerOffline-2026.2.0-linux` — исходный инсталлятор CCDC.
- `ccdc-site-config-2026.2.0-1.tar.gz` — небольшой архив скриптов из этого каталога.

В easyconfig архив добавлен вторым элементом `sources`, его SHA-256 — вторым
элементом `checksums`. `extract_sources = True` включает обработку источников:
инсталлятор копируется в build-directory, а архив распаковывается там в каталог
`ccdc-site-config-2026.2.0-1/`. Рабочий каталог явно закреплён через `start_dir`.
Затем `postinstallcmds` копирует два скрипта в `install-directory/site/`.

Файлы в репозитории:

```text
ccdc/
├── ccdc-2026.2.0-GCCcore-12.3.0.eb
├── ccdc-site-config-2026.2.0-1.tar.gz
└── site-config/
    ├── configure-ccdc.sh
    ├── configure-ccdc.py
    └── make_archive.py
```

На билд-ноде архив должен быть доступен в EasyBuild `sourcepath` вместе с
инсталлятором. В `config/easybuild.env` этого репозитория sourcepath задан как
`/opt/easybuild/sources`, подходящий подкаталог — `c/ccdc/`.

Редактировать нужно исходники в `site-config/`. Пересборка архива из корня
репозитория:

```bash
python3 easybuild/easyconfigs/c/ccdc/site-config/make_archive.py
```

Команда создаёт архив рядом с easyconfig и печатает SHA-256. После изменения
скриптов нужно обновить второй checksum в рецепте. Для новой опубликованной
редакции следует увеличить ревизию `-1` в `ARCHIVE_STEM` упаковщика и в имени
источника и каталога распаковки в easyconfig. Исходный checksum инсталлятора
CCDC при этом не меняется.

Упаковщик включает только два runtime-скрипта, фиксирует метаданные tar/gzip
и не добавляет временные файлы или метаданные macOS. Повторная упаковка тех же
исходников проверяется тестом на побайтовое совпадение. Shell-скрипт определяет
каталог установки по собственному расположению: подстановка EasyBuild внутри
архивных скриптов не требуется.

## Настройка при загрузке модуля

Из распакованного архива устанавливаются два файла внутри каталога программы:

- `site/configure-ccdc.sh` — проверяет доступность четырёх SQLite-файлов базы.
- `site/configure-ccdc.py` — выбирает сервер лицензий и обновляет INI-файлы.

`modluafooter` вызывает shell-скрипт при `ml load ccdc`. Он использует
поставляемый `run_csd_python_api` с параметром Python `-I`; системный Python и
окружение оболочки пользователя не переключаются. Сам `ccdc` при настройке
не импортируется, соединения с серверами лицензий не устанавливаются.

На ноде без доступной базы скрипт сообщает `configuration skipped` и завершает
работу успешно **до создания любых пользовательских файлов**. Поэтому отсутствие
`/db` на билд-ноде не мешает этому рецепту. Установочные команды только записывают
скрипты в `/usr/prog`; sanity checks проверяют локальные файлы и синтаксис shell.

Первая строка `/cm/shared/.site` задаёт сервер:

| Площадка | `floating_licence_server` |
| --- | --- |
| `chbs.arwen` | `http://nrchbs-slp4227.nibr.novartis.net:8090` |
| `ussv.amidala` | `http://nrusca-slp4702.nibr.novartis.net:8090` |
| `uslj.megatron` | `http://nrusca-slp4702.nibr.novartis.net:8090` |
| `usca.logan` | `http://nrusca-slp4702.nibr.novartis.net:8090` |

Для всех площадок используется одинаковый корень базы:
`/db/ccdc/csd/csd/2026/ccdc-data/`. Общие порт `8090` и путь для US подтверждены
заказчиком. Неизвестная площадка или недоступный `.site` приводят к сообщению
`configuration FAILED` без изменения INI-файлов; сервер по умолчанию не выбирается.

Скрипт создаёт отсутствующие файлы и обновляет существующие:

- `~/.config/CCDC/ApplicationServices.ini`: ключ `floating_licence_server`
  в секции `[licensing_v1]`.
- `~/.config/CCDC/CSD.ini`: ключ `root` в секции `[General]`.

Остальные строки сохраняются, включая комментарии, регистр имён, другие секции,
`LastUpdateReminder` и существующий `time_stamp`. Для нового файла лицензии
записывается только сервер; время активации скрипт не придумывает.
`CSD_dev.ini`, `Mercury.ini` и `.csds_defaults3` не изменяются.

Перед изменением существующего файла создаётся отдельная копия
`ApplicationServices.ini.bak.<суффикс>` или `CSD.ini.bak.<суффикс>` в том же
каталоге. Если значение уже правильное, файл и резервные копии не записываются.
Новые INI-файлы и резервные копии имеют права `0600`; у изменяемого INI-файла
сохраняются его исходные права. Параллельные запуски скрипта используют общий lock.
Оба INI проверяются до записи; каждый файл заменяется атомарно. Это не единая
транзакция для двух файлов. При аварии между заменами следующий запуск завершит
настройку; резервные копии сохраняются.

Настройка выполняется перед запуском приложений. `ml show`, `ml spider` и
`ml unload` не запускают скрипт. Выгрузка модуля не восстанавливает старые INI.
Lmod `execute` добавляет команду в оболочку после загрузки окружения, поэтому
ошибка скрипта сама по себе не гарантирует откат загрузки модуля.

## Развёртывание и проверка

1. Передать архив скриптов вместе с easyconfig, разместить архив в `sourcepath`
   и собрать обновлённый рецепт. Для существующей установки одной перегенерации
   modulefile недостаточно: оба файла `site/configure-ccdc.*` должны попасть в
   установку и на целевую ноду вместе с новым модулем.
2. Скопировать содержимое `ccdc-data/csd.installer/` в общий каталог базы.
3. На рабочей ноде с `/db` загрузить модуль заново. Если он уже загружен, сначала
   выгрузить его. У нового пользователя конфигурация лицензии заранее не требуется.

```bash
ml load ccdc/2026.2.0-GCCcore-12.3.0
cat "$HOME/.config/CCDC/ApplicationServices.ini"
cat "$HOME/.config/CCDC/CSD.ini"

run_csd_python_api <<'PY'
from ccdc import io

with io.EntryReader('CSD') as db:
    print('Databases:', db.file_name)
    print('Entries:', len(db))
PY
```

Ожидаются четыре файла из `/db/ccdc/csd/csd/2026/ccdc-data/csd/`. Для ранее
проверенного набора данных получено `1469017` записей. Проверку следует выполнить
на Basel и US; доступность имени сервера или ответ на ping ещё не подтверждают
выдачу лицензии приложению.

Если база стала доступна после загрузки модуля, можно повторно вызвать настройку:

```bash
bash "$EBROOTCCDC/site/configure-ccdc.sh"
```

ConQuest использует отдельные настройки выбора базы. Его работу, а также работу
остальных приложений CCDC, нужно проверить отдельно.

## Локальная проверка

Из корня репозитория:

```bash
python3 -B -m unittest discover -s easybuild/tests -p 'test_ccdc_easyconfig.py' -v
```

Тесты используют временные каталоги, фиктивные файлы базы и замену запуска CCDC
обычным Python. Они проверяют перенос без ссылки, работу Bash/Python-скриптов,
все площадки, новые и существующие профили, отсутствие `/db`, повторные и
параллельные запуски, резервные копии и сохранение других настроек. Дополнительно
проверяются checksum и состав архива, воспроизводимость упаковки, команды
распаковки и соответствие установленных скриптов исходникам. При наличии
Lua/LuaJIT проверяется footer с заменой функций Lmod тестовыми функциями.

Результат 2026-10-30: **20 тестов прошли**, включая `bash -n`, выполнение
скриптов из архива на тестовых данных и проверку footer через LuaJIT.
Эта секция фиксирует команду и результат локальной проверки. Реальная сборка
EasyBuild, запуск через установленный Lmod и выдача лицензий серверами здесь
не выполнялись.
